# R12-B Report — Emerald Audio Leaf Ownership Migration

R12-B migrates ownership of the 569 audio leaf resources (544 direct-sound
samples + 25 programmable waves) from ROM-symbol claims to the resource
pack / session / compat-arena chain, exactly as scoped in
`docs/R12_AUDIO_OWNERSHIP_ARCHITECTURE.md` §"R12-B: audio leaf ownership".
**Additive only**: nothing is removed from the executable, no consumer is
redirected, no State v5 / `HostResolveGbaAddr` / MP2K behavior changes.
The build sounds exactly as pre-R12-B because nothing consumes the arena yet
(duplication of canonical bytes in pack + executable is intentional until
R12-G).

## 2. Canonical payloads

- **Samples**: `AUDIO_SAMPLE` schema 1 `gba-wave-data` — the 16-byte
  `WaveData2` header plus the encoded payload verbatim (ROM slice
  `[rom_offset, rom_offset + encoded_length)`), no AIFF, no transformation.
  `WaveData2` header layout (little-endian): compression flags byte[0..2],
  `freq` u32 @4, `loopStart` u32 @8, `size` u32 @12 (stores sampleCount − 1).
- **Waves**: `gba-cgb-wave` — the exact 16-byte ROM representation (the
  4×16-nibble CGB waveform registers).

Validation mirrors `tools/gen3_resources/audio_family/gen_audio_bindings.py`
`validate_wavedata` exactly (same semantics re-implemented in the C seam and
in the R12-B tests): `freq != 0`; `loopStart <= sampleCount`; uncompressed
(`cf == 0`): `payloadSize == 16 + sampleCount`; compressed: cry-only and
`payloadSize > 16`; waves exactly 16 B. 569/569 pass.

## 3. Provenance (ELF == ROM == manifest == pack payload)

- **ROM**: retail BPEE01 Rev 0, SHA-1 `f3ae088181bf583e55daf962a92bb46f4f1d07b7`
  (`../pokeemerald-reference/pokeemerald.gba`).
- **ELF**: the qualified pret reference build (`../pokeemerald-reference/pokeemerald.elf`,
  provenance string recorded in the manifest: commit d8e405c4f6b48f1faf3b26a3e045f0df2ff3ecb7
  + upstream symbol rename b89722500), previously proven byte-identical to
  retail (see `docs/PRODUCTION_ROM_QUALIFICATION`).
- **Sizes**: derived from the ELF symbol extent — C-compiled arrays carry the
  linker-computed symbol `size` (object layout); size-0 asm labels fall back
  to the binding's artifact size and Guardrail 10 pins it against ELF+ROM.
- **ROM offsets**: `symbol->value - GEN3_GBA_ROM_BASE`; every record is
  range-checked against the ELF bound, the 16 MiB image, and the duplicate
  range check (no two records share a ROM slice, except explicitly allowed
  shared ranges).
- **Re-proof in-runner** (`tests/gen3_resources/run_audio_leaf.sh` E1/E2):
  - `gen3-pack-build --check` with the 7 manifests + 7 catalogs reproduces
    the committed production pack **byte-for-byte** (5087 entries);
  - `gen3-elf-manifest --check` re-derives the audio manifest **byte-for-byte**
    from ELF + ROM + catalog + bindings.
- The seam additionally cross-checks per leaf: pack payload vs session view
  (provider `emerald.rom-base.bpee01` resolving the same key) — size AND byte
  equality — so the arena always copies session bytes, never pack-only bytes.

## 5. Arena implementation (`src/emerald/resources/emerald_audio_compat.c`)

One consolidated, process-lifetime arena, published transactionally:

- **Constants** (header): `EMERALD_AUDIO_ROM_START 0x0867709C`,
  `EMERALD_AUDIO_SPAN_END 0x089A3DB4`, `EMERALD_AUDIO_SPAN_SIZE 3,329,304 B`.
  `arenaOffset = romAddr - EMERALD_AUDIO_ROM_START` — the verbatim zone sits
  at ROM-relative offsets inside the arena, so a later consumer can index it
  by GBA address without translation tables.
- **Sparseness decision**: the zone is ~3.3 MiB for 2.38 MiB of payloads
  (~72% utilization; the span is dense — the leaves are the audio sample
  region of the ROM, interleaved with tables that are *not* migrated).
  R12-B item 6 authorised this; accepted.
- **Layout**: one `malloc(sizeof(header) + recordBytes + SPAN_SIZE)` with
  overflow-checked arithmetic; header + leaf table at `[0, recordBytes)`,
  verbatim zone at `[recordBytes, recordBytes + SPAN_SIZE)`, zero-initialised
  (so uncovered holes read back as zeroed, and a probe confirms one). Leaf
  records carry `canonicalName`, key, kind, `sourceRomOffset`, `arenaOffset`,
  `payloadSize`, `payloadSha256`.
- **Transactional**: phase 1 validates every leaf before any allocation —
  composition gate (counts by kind), resolution via the session
  (`Gen3ResourceHandle_Resolve`), type `AUDIO_SAMPLE` + schema 1, winning
  provider must be `emerald.rom-base.bpee01`, payload size + byte equality vs
  the session view, span-bounds check with overflow guard. Phase 2 performs
  the single allocation and the verbatim memcpy. On any failure the arena
  stays absent and the diagnostics name the first failing leaf
  (canonical name, stage, expected/actual type/schema/size, winning
  provider).
- **Publication**: `sArena` swap is atomic (single pointer store); a
  relocated session (save/load path) re-resolves and the swap replaces the
  old arena; `Republish` re-derives from the current snapshot.

## 6. Seam API + startup wiring

`include/emerald/resources/emerald_audio_compat.h` (contract) +
`src/emerald/resources/emerald_audio_compat.c`:

- `TryInitialize(snapshot, pack, diag)` — transactional publish (above).
- `Republish(diag)` — re-publish after session relocation.
- `ClearMigratedEntries()` / `Shutdown()` — fail closed (arena becomes
  absent; consumers get `ERR_UNAVAILABLE`).
- `GetArena(&base, &size)`, `GetPublishedCount()`, `GetLeafSpan(name, &off, &size)`,
  `GetLeafBytes(name, &bytes, &size)` — query/test helpers.
- Diagnostics: `canonicalName`, `stage`, `expected/actualType`,
  `expected/actualSchema`, `expected/actualSize`, `winningProviderId/Version/Precedence`.

**Wiring** (`src/emerald/resources/emerald_runtime_loader.c`, the only
modified non-test source): `RegisterRuntimeSnapshot` calls
`EmeraldAudioCompat_TryInitialize` after `InitializeFromSnapshot` succeeds —
**additive by contract**: a failure prints named diagnostics to stderr and
degrades (no arena), never refuses the session, and nothing consumes the
arena yet, so the build sounds exactly as pre-R12-B.

## 11. R12-C blockers / next steps

R12-B is complete and STOPPED per instructions (no commit). R12-C (the
next stage) will need:

1. **Voicegroup/cry-table/keysplit migration design** — the R12-A audit
   listed 1,301 proposed resources (voicegroups, cry tables, keysplit
   runs, songs/track streams); restore the 76 canonical `.aif` sources
   before R12-B→C (R12 audio audit finding) so compressed-cry provenance
   can be re-derived from sources rather than the ROM only.
2. **Arena range registration** for mid-play saves (R12 audio audit:
   "mid-play saves need range registration") — the arena must participate
   in the range-index so save/load relocation keeps `GetLeafBytes` valid.
3. **R12-G consumer redirect** — only then do compiled payloads leave the
   executable; that is a separate, explicitly out-of-scope stage.
