# R13-H4 — Animation & Field-Effect Live Cutover Report

Status: **complete**. Battle animation scripts and field-effect scripts
execute from the H ROM-backed resource arenas (family
`BATTLE_ANIM_SCRIPT` + `FIELD_EFFECT_SCRIPT`) through the production live
seam, published transactionally by the R6 loader. The anim interpreter
(`src/battle_anim.c`) and the field-effect interpreter
(`src/field_effect.c`) were cut over to typed H resolution with no
bytecode format change. The live range count is **6,379 / 8,192** (the
6,377 G/script-family ranges plus exactly 2 H live ranges). Ownership
stays `COMPILED_PENDING_MIGRATION` (anim 658/658, FE 68/68); no compiled
H payload was removed and nothing was committed.

Baseline: `checkpoint-r13h3-complete` (commit `e3bd719c7`).
Qualified ROM: `../pokeemerald-reference/pokeemerald.gba`
(SHA-1 `f3ae088181bf583e55daf962a92bb46f4f1d07b7`).

## 1. Result

Both families are live on the H arena with the transactional
publication order required by the brief: validate anim surface → validate
FE surface → stage → register ranges → publish routing → enable execution
→ commit, failing closed and preserving the prior generation. The
differential oracles prove byte-exact module execution on both arena
layouts (GBA-preserving and tight-packed reversed) for all 723 payload
modules; the 11-case fail-closed fault matrix, the generation-replacement
proof (6,379 invariant + identity-specific unregister), and the
fresh-process State-v5 anim proof (mandatory §15) all pass. The release
and DINFO forced builds both verify the qualified ROM hash; the pack
stays at exactly 23,069 entries.

## 3. Exact live ranges (brief §5)

Production registration is exactly **6,379 / 8,192** live ranges: the
6,377 G/script-family ranges plus the **2 H live ranges** (anim + FE),
both registered through `RegisterRanges` in the loader transaction
(anim family schema 48, FE family schema 51). `GetRangeCount` is asserted
== 6,379 in the loader gate and in the fault matrix before and after
publish; any deviation is a STOP condition (none hit).

| Quantity | Value |
|---|---|

| Anim payload | 650 BYTECODE + 5 ROUTING = 655 modules |
| FE payload | 67 BYTECODE + 1 ROUTING = 68 modules |

| Refuse-only bindings | 4 (indexes 280, 402, 446, 461), 20 operand positions |
| Boundaries | 9,818 |

Identity is family → module → offset everywhere: the live resolver takes
a family tag plus the module's `gbaStart`, and every resolved pointer is
derived by boundary containment from the canonical byte image; zero-width
aliases are canonicalized to their 1-byte backing module (3 in anim), so
no alias has a distinct address.

## 5. Anim interpreter cutover (brief §7)

Minimum runtime readers, typed H resolution, no bytecode format change:

- `LaunchBattleAnimation` — the only entry: resolves
  `animsTable[tableId]` under family `BATTLE_ANIM_SCRIPT` via
  `ResolveLaunchTarget` (root export only); any refusal is fail-closed
  (animation does not launch).
- The 9 commands that read absolute script words from the active arena
  (`createsprite`, `createvisualtask`, `call`, `choosetwoturnanim`,
  `jumpifmoveturn`, `goto`, `createsoundtask`, `jumpargeq`,
  `jumpifcontest`) resolve their operands through `ResolveOperand` with
  the family gate. `jumpargeq` reads its operand unaligned at +3 — the
  resolver is word-boundary-correct for the reloc's actual operand
  offset, not the command header.
- All other commands are unchanged (relative bytecode, immediates,
  arguments) — the bytecode format is untouched; only the read paths that
  dereference absolute words were converted.

## 6. SCRIPT_TARGET resolution (brief §8)

`ResolveScriptTarget` semantics: family gate → `NOT_PUBLISHED` /
`UNAVAILABLE` → word-set binary search (715 words) → `GbaContain` of the
word → family mismatch → `INSTRUCTION_START` boundary check. `ResolveOperand`
on a `SCRIPT_TARGET` reloc: `ReverseContain` the operand's host address →
find the reloc → word equality check → resolve boundary + base pointer.
An operand word that matches the raw H2 metadata but fails any gate is a
hard refusal — there is no compiled fallback (brief §23).

## 7. Sprite templates (brief §9)

Semantic binding table only: `ENGINE_SPRITE_TEMPLATE_TARGET` relocs map
engine template slots to H payload words; the resolver returns the arena
address of the template payload — no GBA→host arithmetic on template
pointers anywhere.

## 8. Engine callbacks (brief §10)

`ENGINE_CALLBACK` relocs resolve through the semantic binding table
(`kBindingTable`, 620 rows). Unknown binding index = hard refusal
(`ERR_REFUSED`); the 4 refuse-only bindings (gShakeMonOrTerrainSpriteTemplate,
AnimTask_LoadMistTiles, AnimTask_ShakeBattleTerrain,
AnimTask_GetBattleTerrain — 20 operand positions) are exercised by the
oracle's refuse-only probe and never resolve.

## 9. Misc engine targets (brief §11)

Generated semantic bindings for the remaining engine-target classes
(`ENGINE_GFX_TARGET`, `ENGINE_TABLE_TARGET`) — 36 FE gfx bindings
(ground/bg tiles, palettes) and 67 FE callnative refuse-if-unknown
bindings — resolved by binding index, never by pointer arithmetic.

## 10. Scalars/IDs never converted (brief §12)

Scalars and IDs travel as integers end-to-end. The only values the
resolver ever converts are reloc-covered words inside arena payloads; a
non-reloc word (gap) refuses (§24 case 7), a compiled pointer refuses
(§24 case 8), and no persisted state record holds an H pointer (§22).

## 11. Anim IP + return pointer in the active H arena (brief §13)

The anim VM state (`sBattleAnimScriptPtr`, `sBattleAnimScriptRetAddr`,
`gAnimScriptCallback`) is registered with the State-v5 layout
(`BattleAnimCompat_RegisterStateLayout` → `EmeraldBattleState_SetLayout`)
and every live value is a pointer into the published arena (verified by
the fresh-process proof, §14 — module + offset identity restored into the
new generation's arena, never a stale host address).

## 12. Live State-v5 anim activation (brief §14) + fresh-process proof (brief §15 — HARD GATE)

`emerald_battle_state.c` now owns the anim family for identity capture.
The H4-CREATE/H4-LOAD drivers stage the anim arena, plant an active anim
VM (module 0, IP at instruction 4, return at +19), capture the ordinary
State-v5 sidecar, destroy the staging generation, and restore in a fresh
process at a forced-different arena base. The module + offset identity
is re-resolved against the new generation's layout and the restored IP
executes the exact next canonical opcode:

```
H4 fresh-process relocation: creator ('0x303a3ef0','1','0','4','19')
                             -> restorer ('0x3a2518c1','2','0','4','19')
H4 state: live anim IP/return relocated by module+offset identity into the new arena
```

Identity tuple (arena base, generation, module, ip, ret) is identical
across the process boundary. This gate passed on every run (H3 baseline
values differ per-ASLR; the identity digits are invariant).

## 13. Routing table publication (brief §17)

The anim family publishes 5 ROUTING payload modules (gMovesWithQuietBgm,
gBattleAnims_Moves, gBattleAnims_StatusConditions, gBattleAnims_General,
gBattleAnims_Special) and FE publishes 1 (gFieldEffectScriptPointers) —
their canonical routing bytes live in the arena. ROUTING modules are not
launchable: `ResolveLaunchTarget` gates `mapKind != BYTECODE` →
`ERR_BOUNDARY_INVALID`, so the launch path can never enter a routing
table. The production routing tables remain native in
`data/battle_anim_scripts.s` (live cutover; physical removal later, §32).

## 14. FE cutover (brief §18-22)

- 68 modules / 817 B payload (67 BYTECODE + 1 ROUTING), 170 relocs, all
  gfx bindings semantic (36), all callnative bindings refuse-if-unknown
  (67).
- `FieldEffectStart` resolves `gFieldEffectScriptPointers[id]` under
  family `FIELD_EFFECT_SCRIPT`; refusal removes the active effect and
  returns 0 (the effect never starts).
- The four operand-reading helpers (LoadTiles / LoadFadedPalette /
  LoadPalette / CallNative) are now `bool8` and return FALSE on refusal,
  aborting the command loop; the combined commands short-circuit.
- State policy: the FE transient pointer is never serialized — FE has no
  persistent state identity path in this stage.

## 15. Compiled-fallback prohibition (brief §23)

There is no compiled fallback anywhere in the live path. Every refusal
terminal is fail-closed: `LaunchBattleAnimation` returns without
launching, `FieldEffectStart` removes the effect and returns 0, the FE
helpers abort the command loop, `ResolveAnimOperand` calls
`AbortBattleAnimation` on non-OK. The oracle's byte-exact check runs the
H payloads on both layouts with zero divergence; the compiled tables
never receive an anim/FE launch in the live build (their only remaining
readers are the physical-removal stage).

## 17. Generation replacement (brief §25)

`DoReplace` stages generation A (layout 0), commits, then stages
generation B (layout 1) from the same session: stage-complete-first,
register, publish; the 6,379 invariant holds across the swap
(`H4-REPLACE genA=1 genB=2 arena-a=0x… arena-b=0x… count=6379`);
unregister is identity-specific (`UnregisterRange(canonicalName)` for the
two live families, `UnregisterRanges` for the full rollback), and
re-registration restores resolution.

## 18. Range lifecycle (brief §26)

Live ranges stay 6,379 (2 H + 6,377) through load, publish, replacement,
and teardown. `ClearMigratedEntries` unpublishes both live ranges (count
back to 6,377) without touching sibling ranges; re-publish restores.
Zero-width aliases are canonicalized (§4), so no alias contributes a
distinct range.
